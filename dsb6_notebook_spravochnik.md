## 1. Что такое Jupyter Notebook

**Jupyter Notebook** — это «интерактивный документ», где живут рядом:
- **код** (Python),
- **результаты его выполнения** (таблицы, числа, графики),
- **текст** (объяснения, выводы, Markdown-заметки).

Всё — в **ячейках**, которые выполняются по одной, сверху вниз, и каждый результат
остаётся на месте прямо под кодом, который его создал.

Простая мысль: **обычный .py-файл — это инструкция для компьютера. Ноутбук — это рассказ
с доказательствами** (код = доказательство, текст = рассказ).

Файл ноутбука имеет расширение `.ipynb` (iPython Notebook).

---

## 2. Зачем нужен / почему существуют ноутбуки

Они появились, чтобы решить проблему учёных и аналитиков:
раньше расчёт жил в скрипте, а объяснение — в отчёте/статье, и они расходились.
Ноутбук соединяет их в одном месте.

Три главные причины использовать ноутбук:

| Причина | Что это даёт |
|---|---|
| **Интерактивность** | Выполнил ячейку — сразу видишь результат. Не нужно запускать весь скрипт целиком. |
| **Повествование** | Код + текст рядом. Читатель видит «вопрос → код → ответ» как историю. |
| **Эксперименты** | Можно менять одну ячейку и перезапускать её без перезапуска всего. |

---

## 3. В каких случаях лучше использовать ноутбук, а в каких — нет

### Ноутбук — ХОРОШ, когда:
- **исследование / анализ** (посмотрел данные → гипотеза → проверил → вывод);
- **демонстрация** результата другому человеку (защита проекта!);
- **обучение** (показать шаг за шагом, что происходит);
- **отчёт по данным** (графики + текст + таблицы в одном файле).

### Ноутбук — ПЛОХ, когда:
- **продакшн-код** (сервисы, API, боты) — нужен обычный модуль, а не ячейки;
- **код, который работает по расписанию** (cron) — ноутбук не для этого;
- **большой сложный проект** (100+ функций) — в ноутбуке тяжело тестировать и рефакторить;
- **чистая библиотека** — тесты, упаковка, переиспользование — это модули.

> Золотое правило: **логика живёт в модуле (.py), ноутбук — только для показа результатов.**
> Ровно так устроен DSB6: вся работа в `movielens_analysis.py`, а ноутбук только вызывает методы.

## 4. Как устроен ноутбук: ячейки

Ноутбук состоит из ячеек. Два главных типа:

### Кодовая ячейка (Code)
```python
movies = Movies('ml-latest-small/movies.csv')
print(movies.dist_by_release())
```
После запуска (Shift+Enter) под ней появляется вывод.

### Текстовая ячейка (Markdown)
Пишется обычным текстом с простой разметкой:
```markdown
# Заголовок
**жирный**, *курсив*, списки, таблицы
```
Пример таблицы в Markdown:
```markdown
| Год | Фильмов |
|-----|--------|
| 1995| 224    |
```

### Полезные правила поведения ноутбука
- Ячейки выполняются **в том порядке, в котором ты их запускал** (сверху вниз,
  если запускаешь по очереди) — поэтому запускай по порядку.
- Переменные «живут» между ячейками: создал в одной — пользуешься в следующих.
- **Ядро (kernel)** — это Python-процесс, который помнит все переменные. Кнопка
  «Restart» = начать всё с чистого листа (переменные пропадают).

## 5. Про %timeit (главное требование README DSB6)

Магия **`%timeit`** замеряет, сколько времени выполняется код ячейки:

```python
%timeit movies.dist_by_release()
```
Вывод вроде: `12.3 ms ± 0.5 ms per loop` — означает: в среднем ~12 миллисекунд
на один прогон, разброс ±0.5 мс.

Почему так важно в DSB6: README (глава VIII) требует, чтобы **в каждой ячейке,
где есть замер, стоял `%timeit`**. Это часть оценки — показываешь, что умеешь
измерять производительность кода (навык из DSB5 в действии).

**Как правильно ставить:**
- `%timeit` пишется **в начале самой ячейки** до кода;
- он прогоняет код МНОГО раз и берёт среднее — поэтому не пугайся, что
  «тормозит», это он измеряет;
- если ячейка медленная — можно `%timeit -r 1 -n 1` (по одному разу), но лучше
  оставить стандартный вызов — он честнее.

## 6. Кастомизация — нужна ли

Коротко: **в DSB6 — нет, не требуется.** README не требует тем, плагинов или
каких-то настроек. Хватит стандартного Jupyter.

Но знать, что существует, полезно (для будущего):

| Кастомизация | Что даёт | Нужна ли сейчас |
|---|---|---|
| **Темы** (JupyterLab themes) | тёмная тема для глаз | нет |
| **Плагины/расширения** (nbextensions) | автодополнение, оглавление | нет |
| **Графики inline** (`%matplotlib inline`) | графики прямо под ячейкой | появится, когда дойдёшь до графиков |
| **Отображение таблиц** (`df.style`) | красивые цветные таблицы | в DSB6 нет pandas — мимо |
| **nbconvert** | экспорт .ipynb в HTML/PDF (для сдачи!) | **полезно знать** |

Для защиты проекта можно разве что поставить тёмную тему, чтоб глазам легче —
и то необязательно.

## 7. Зачем ноутбук именно в этом проекте (DSB6)

DSB6 — командный проект «MovieLens Analytics». Сдаётся **два файла**:
1. `src/movielens_analysis.py` — модуль с классами (вся логика, её ты уже написал);
2. `src/movielens_report.ipynb` — ноутбук-отчёт (показывает работу классов).

Ноутбук здесь играет роль **демонстрации**: он доказывает проверяющему, что
классы работают, вызывая **каждый метод по очереди и показывая результаты**.
Как презентация исследования: «вот данные → вот вопрос → вот ответ → вот вывод».

Из README (жёсткие требования к ноутбуку):
- импорт **только** из модуля (никакого pandas/всяких библиотек сверх разрешённых);
- **каждый метод** классов использован хотя бы раз;
- в каждой ячейке с замером — `%timeit`;
- можно (и стоит) показать, что результаты методов совпадают с «ручным» расчётом.

## 8. Как использовать ноутбук для этого проекта (пошагово)

Запуск ноутбука (в каталоге `src/`):
```bash
python -m jupyter notebook
# или
python -m jupyter lab
```
Дальше в списке открываешь `movielens_report.ipynb`.

Проверить, что Jupyter установлен в твоём venv:
```bash
src/DSB6/bin/python -m jupyter --version
```
Если нет — поставить: `src/DSB6/bin/pip install jupyter` (нужно быть в venv).

### Минимальная структура отчёта (сделай так — этого хватит):

1. **Markdown-ячейка** — название проекта, авторы.
2. **Кодовая ячейка** — импорт из модуля:
   ```python
   from movielens_analysis import Movies, Ratings, average, median, variance
   ```
3. **Обзор данных** — создать объекты и показать количество:
   ```python
   %timeit Movies('ml-latest-small/movies.csv')
   movies = Movies('ml-latest-small/movies.csv')
   print('Фильмов:', len(movies.rows))
   ```
4. **Методы Movies** — по одному на ячейку с `%timeit`:
   ```python
   %timeit movies.dist_by_release()
   print(movies.dist_by_release())
   ```
5. **Методы Ratings.Movies и Ratings.Users** — так же, по одному на ячейку.
6. **Финальная Markdown-ячейка** — короткий вывод: что нашли (самый частый год,
   самый популярный фильм и т.п.).

Следи: **каждая кодовая ячейка с замером начинается с `%timeit`** — это пункт
оценки. Для наглядности можно после `%timeit` отдельной строкой `print(...)`
результат (в одной ячейке магия + print работают).

## 9. Перспективы: ноутбук для тебя как data scientist

Если ты продолжишь в аналитике/ML, ноутбук станет твоим **основным рабочим
инструментом № 1**:

- **Kaggle / соревнования** — все решают задачи именно в ноутбуках;
- **исследование данных (EDA)** — первые 80% любой ML-задачи (посмотреть,
  почистить, понять) делаются в ноутбуке;
- **статьи и портфолио** — ноутбук = интерактивная демонстрация навыков,
  которую легко показать (`.ipynb` на GitHub открывается прямо в браузере);
- **обучение** — твой стиль «читать с телефона» отлично сочетается:
  в ноутбуке можно перечитывать Markdown-пояснения и перезапускать ячейки.

Что навыки из DSB6 дадут тебе в будущем:
- `Movies.dist_by_release()` — это про **группировку данных** (grouping);
- `dist_by_genres` — про **агрегацию** (сколько чего в каждой категории);
- `top_by_num_of_ratings` — про **топ-N запросы** (как SQL: ORDER BY LIMIT);
- `variance` — база **статистики** (разброс данных);
- `%timeit` — замер производительности, ежедневная практика DS.

То есть ты уже сейчас, на DSB6, делаешь руками то, что data scientist делает
каждый день: читает CSV → группирует → считает статистику → показывает результат
в ноутбуке. Это и есть «маленькая работа аналитика» целиком.
