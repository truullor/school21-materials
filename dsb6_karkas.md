# DSB6 — Как устроен каркас (зачем всё это)

## Проблема
Данные лежат в 4 файлах. У каждого свой класс (Movies, Ratings, Tags, Links).
Если каждый будет заново открывать/парсить свой файл — куча одинакового кода.

## Решение: общий базовый класс
```
BaseDataset  ← читает файл ОДИН раз, кладёт данные в атрибут
    ↑ наследуются и получают готовые данные
Movies  Ratings  Tags  Links
```

- `BaseDataset.__init__(path)` — открывает файл через `read_csv()`, сохраняет `self.header` (заголовок) и данные.
- Каждый класс (Movies и т.д.) — НЕ открывает файл сам. В `__init__` достаточно вызвать `super().__init__(path)`, и всё готово. Либо наследник вообще не пишет `__init__` — возьмёт родительский.
- Методы (`dist_by_release` и т.д.) работают только с уже готовыми данными в атрибуте класса.

## Почему `read_csv` такой длинный
В названиях фильмов есть запятые в кавычках: `"American President, The (1995)"`.
Просто `split(",")` сломал бы строку на лишние куски. Поэтому `read_csv` аккуратно
обходит кавычки (переключатель `in_quotes`) и разделяет только по настоящим запятым.

## Согласованность — самое важное
Все классы ДОЛЖНЫ брать данные из одного и того же места (атрибута) и в одном формате.
Поэтому и договариваемся с Б: `self.tail` или `self.rows` — ОДНО имя на двоих.
