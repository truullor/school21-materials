## 0. Суть проекта

**DSB1 = UNIX: инструменты командной строки.** Учились брать данные о вакансиях и преобработывать их утилитами UNIX: `curl`, `sort`, `uniq`, `jq`, `sed`, `cat`, `awk`, `head`, `tail`.

Жёсткие требования задания (помни на защите):
- Все скрипты на `#!/bin/sh`, **исполняемые** (`chmod +x`).
- Сдаём только в ветку **`develop`** (master игнорируется).
- Работаем в каталоге `src/`.
- В каталоге не должно быть лишних файлов сверх указанных в задании.
- Результат считается **честно** скриптами, не подменяется готовым выводом.

## 2. По упражнениям

### ex00 — Получение данных
- **Файлы сдачи:** `hh.json` (скрипт `hh.sh` — опционально, не делали).
- **Что сделано:** использован **альтернативный вариант** из README — скопирован `materials/hh.json` в `src/ex00/`. Это явно разрешено заданием («если поджимает время»).
- **Содержимое:** 20 вакансий Data Scientist, pretty-printed JSON (каждое поле на новой строке).
- **Почему не через API:** регистрация приложения на dev.hh.ru занимает время; альтернатива допустима.

### ex01 — JSON → CSV
- **Файлы сдачи:** `filter.jq`, `json_to_csv.sh`, `hh.csv`.
- **Утилиты:** `jq`, `echo`, перенаправление `>`.
- **`filter.jq`:** `.items[] | [.id, .created_at, .name, .has_test, .alternate_url] | @csv`
  — берёт массив `items`, для каждой вакансии собирает 5 полей в массив, `@csv` форматирует как CSV-строку с кавычками.
- **`json_to_csv.sh`:** `( echo '"id","created_at","name","has_test","alternate_url"'; jq -r -f filter.jq ../ex00/hh.json) > hh.csv`
  — сначала печатает заголовок, затем jq выдаёт строки данных; всё в `hh.csv`.
- **Зачем отдельный `filter.jq`:** фильтр вынесен в файл (требование задания), скрипт только вызывает его — переиспользуемо и читаемо.

### ex02 — Сортировка
- **Файлы сдачи:** `sorter.sh`, `hh_sorted.csv`.
- **Утилиты:** `head`, `tail`, `sort`.
- **`sorter.sh`:** `( head -1 hh.csv; tail -n +2 hh.csv | sort -t ',' -k2,2 -k1,1n ) > hh_sorted.csv`
  - `head -1` берёт заголовок, `tail -n +2` — данные без заголовка.
  - `sort -t ','` — разделитель запятая.
  - `-k2,2` — сортировка по 2-й колонке (`created_at`) как по строке.
  - `-k1,1n` — затем по 1-й колонке (`id`) **численно** (`n`).
- **Зачем `head`/`tail` разрыв:** чтобы заголовок не попал под сортировку.
- **Зачем `n` у id:** иначе `id` сортировался бы как текст (`10` < `2`).

### ex03 — Замена строк (предобработка)
- **Файлы сдачи:** `cleaner.sh`, `hh_positions.csv`.
- **Утилиты:** `cat`, `head`, `tail`, `sed`.
- **Логика `sed`:** цепочка правил, каждое проверяет колонку `name` (3-я):
  1. `Middle/Senior` → `"Middle/Senior"` (проверяется **первым!**)
  2. `Junior` → `"Junior"`
  3. `Middle` → `"Middle"`
  4. `Senior` → `"Senior"`
  5. иначе → `"-"`
  - `;t` после каждой замены: если замена прошла — перейти в конец скрипта (не применять остальные правила).
- **Почему `Middle/Senior` первым:** иначе строка `"Middle/Senior"` совпала бы с правилом `Senior` и превратилась бы в `"Senior"`, потеряв `Middle`. Порядок важен.
- **Результат:** колонка `name` заменена на грейд; строки без грейда → `"-"`.

### ex04 — Описательная статистика
- **Файлы сдачи:** `counter.sh`, `hh_uniq_positions.csv`.
- **Утилиты:** `tail`, `cut`, `sort`, `uniq`, `awk`.
- **`counter.sh`:** `echo '"name","count"' > hh_uniq_positions.csv; tail -n +2 hh_positions.csv | cut -d ',' -f3 | sort | uniq -c | sort -rn | awk '{print $2","$1}' >> hh_uniq_positions.csv`
  - `cut -d ',' -f3` — вытащить колонку `name`.
  - `sort | uniq -c` — посчитать уникальные значения (`-c` добавляет счётчик).
  - `sort -rn` — отсортировать по счётчику по **убыванию** (`r`=reverse, `n`=числом).
  - `awk '{print $2","$1}'` — поменять местами: было `счётчик пробел имя` → `имя,счётчик`.
- **Реальный результат (данные 2025):** `"Junior",8`, `"Senior",1`, `"Middle",1`, `"-",10` (20 вакансий суммарно).

### ex05 — Разбиение и конкатенация
- **Файлы сдачи:** `partitioner.sh`, `concatenator.sh`.
- **`partitioner.sh`** (утилиты: `head`, `tail`, `awk`):
  - сохраняет заголовок; для каждой строки `substr($2, 2, 10)` вырезает дату (`YYYY-MM-DD`) из `created_at` (пропускает первую кавычку, берёт 10 символов);
  - пишет строку в файл `<дата>.csv`, заголовок — только при первом появлении даты.
  - **Результат:** 14 файлов `2025-10-06.csv` … `2025-11-03.csv`.
- **`concatenator.sh`** (утилиты: `head`, `tail`, `for`):
  - пишет заголовок из `hh_positions.csv`;
  - `for file in 2025-*.csv` — для каждой партиции дописывает данные (`tail -n +2`, без её заголовка).
  - **Результат `hh_positions_concatenated.csv` совпадает с ex03** (проверено `diff` — пусто).

## 4. Возможные вопросы пира + ответы

**Q: Зачем `filter.jq` отдельно от скрипта?**
A: Задание требует фильтр в отдельном файле; плюс переиспользуемость и читаемость — скрипт только вызывает `jq -f filter.jq`.

**Q: Что делает `@csv` в jq?**
A: Превращает JSON-массив в CSV-строку с правильными кавычками и запятыми.

**Q: Почему `sort -k2,2 -k1,1n`?**
A: Сначала по `created_at` (2-я колонка, как строка), затем по `id` (1-я) численно (`n`), чтобы `10` шло после `9`, а не перед `2`.

**Q: Зачем в ex02 `head -1` и `tail -n +2`?**
A: Чтобы заголовок не участвовал в сортировке и остался первой строкой.

**Q: Как `sed` в ex03 не сломал `Middle/Senior`?**
A: Правило `Middle/Senior` проверяется первым, а `;t` останавливает цепочку после первой успешной замены — поэтому строка не превращается в `"Senior"`.

**Q: Что значит `;t` в sed?**
A: `t` — переход в конец скрипта, если предыдущая замена сработала (short-circuit).

**Q: Почему `cut -f3` в ex04?**
A: Колонка `name` — третья в `hh_positions.csv`.

**Q: Зачем `sort -rn` в ex04?**
A: `r` — по убыванию, `n` — численно (по количеству, а не лексикографически).

**Q: Как `partitioner.sh` достаёт дату?**
A: `substr($2, 2, 10)` — из поля `created_at` берёт 10 символов, начиная со 2-го (пропуская открывающую кавычку): `YYYY-MM-DD`.

**Q: Почему `concatenator.sh` ищет `2025-*.csv`?**
A: Потому что данные за 2025 год, и партиции названы по датам. **Ограничение:** при данных другого года глоб надо менять (или делать `*.csv`).

**Q: Почему в ex00 не через API?**
A: Использован разрешённый альтернативный вариант — копия `materials/hh.json`.

**Q: Результат подменён заранее?**
A: Нет, всё генерируется скриптами честно; конкатенация совпадает с ex03 (проверено diff).

**Q: Какие утилиты использовал больше всего?**
A: `sort` (ex02, ex04), `sed` (ex03), `awk` (ex04, ex05), `jq` (ex01), `cut`/`uniq`/`head`/`tail`/`cat`.
